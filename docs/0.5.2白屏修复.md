# 0.5.2：开始分析后白屏修复

## 实际原因与证据

用户在分析总览、AI分析台均报告点击开始分析后整页空白。新建浏览器正常条件下多次分析、切换年份、三种模式、五国和两个数据包均返回200，未复现；部署异常边界和本地诊断后，捕获到用户浏览器的真实异常：

`Failed to execute 'insertBefore' on 'Node': The node before which the new node is to be inserted is not a child of this node.`

组件堆栈指向按钮内的图标。原通用Button将可切换图标与裸文字并列放置；网页翻译或类似DOM改写将文字节点替换为font等节点后，React仍把旧文字节点当作插入锚点。点击分析切换Search与LoaderCircle时插入失败，未隔离异常导致React整页卸载。

使用原0.5.0交付包的真实前端资源，模拟替换按钮文字节点后点击开始分析，复现完全相同insertBefore错误，main节点数变为0。该复现确定了触发机制，不推断用户具体安装了哪一种插件。

## 修复

- 通用按钮的每个图标、文字子项分别包在稳定容器中；图标替换不再依赖裸文字锚点。商品标签名称也加容器。
- 页面声明不自动翻译，避免第三方翻译改写交互节点；没有清理浏览器研究笔记或用户保存记录。
- 增加React异常边界，其他显示异常显示恢复入口，不再让根界面直接变成空白。
- 图表初始化、尺寸观察及销毁增加错误隔离；绘图能力不可用时保留明细、证据与重试入口。先检查绘图上下文，避免图表库半初始化后清理异常。
- 首页及index.html使用no-store，避免刷新后继续加载旧入口；哈希资源仍按现有静态方式提供。
- 本地output/client-errors.jsonl记录限长、脱敏的显示错误与组件堆栈；不上传外部服务，不收集配置、问题或浏览器存储。相同错误去重，每次页面最多20类。
- 研究笔记缓存只恢复合法对象中的字符串字段，避免损坏的缓存进入界面状态。

## 验证

- 用户在0.5.1保护版强制刷新后反馈“已正常显示分析结果”；0.5.2进一步保留结构性按钮修复。
- 原版模拟文字改写：insertBefore，main=0，白屏；修复版同样文字改写：分析正常，三种模式与AI页均通过，无未捕获异常。
- 最终图表故障注入：页面和数值保留，显示局部提示；恢复绘图能力后可重试成功。故障注入日志属于开发检查，不是用户真实错误或模型成绩。
- 全量102项Python回归通过；新增首页缓存检查、诊断字段限长及脱敏检查。生产前端构建通过。
- 可复用浏览器检查：scripts/check_display_browser.js，通过Playwright CLI的run-code执行；不发送模型问题。
- 未调用DeepSeek，没有改变原分析计算口径、保存记录、已有PDF材料或冻结评测结果。
