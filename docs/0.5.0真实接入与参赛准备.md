## 已定位与改进

1. 原完整Spec包含非当前模式的默认reporter和partner，模型误把它们当作当前多国角色。现由model_scope仅传入有效角色，并同步过滤证据和窗口中的Spec。
2. 模型将x0、x1等字段代码放进正文，触发无自由数字规则。补充自然语言表达约束，字段代码只允许出现在numbers.field，不放宽输出校验。
3. 明确各工具参数示例与模式限制，减少无关partners、base_years等参数。
4. 兼容调用明确输出长度、检查空响应和结束原因；DeepSeek使用非思考模式执行受限JSON任务。调用日志保存请求消息、返回正文、模型名、用量与耗时，不保存Authorization头和私有思考内容。
5. 按用户“只3题”限制，修复后未追加真实调用，只完成测试替身回归。不能声称修复后的模型成功率已经提高。

首轮代码、数据、参考与提示的11份文件按原指纹保存在evaluation/deepseek-20261019-v1/frozen。执行脚本与6份首次任务结果另做运行后封存，不将后封存说成事前冻结。当前源代码已修订，直接重跑v1会因代码指纹不符而拒绝；下一次必须新建版本并使用未运行题，旧3题转回归题。

独立语义评价使用independent-review-template.json的副本，填写0/1/null、理由及匿名评价者代号，不覆盖首次结果或原模板。当前没有独立评价成绩。

## 用户试用闭环

应用新增“试用与演示”：匿名代号、默认开发排练、三项标准任务、服务器起止时间、实际答案、卡点与费力度、JSON导出。开始任务会载入相应分析；操作后返回工作台提交。已完成任务不能在同一会话覆盖首次结果。

排练和真实参与者模式分别保存。参与者会话数不等于独立人数，自报完成不等于观察者确认。耗时是墙钟时间，包含等待和中断。当前浏览器验收仅创建QA_REHEARSAL_05排练，真人会话0、独立核实结果0。参赛者需自行邀请目标用户并记录实际情况，不可直接把排练当作用户成绩。
